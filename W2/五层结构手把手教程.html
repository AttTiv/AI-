DAY 1 · 第一个任务 · 手把手教程

系统提示词五层结构

搞懂它是什么、为什么要分层、以及怎么把一坨提示词拆成五层。跟着做完，你会拿到一份能长期复用的模板。

预计 45 分钟学 + 60 分钟练 零基础可跟 含 5 个动手练习 · 附参考答案 不需要写代码

开场先看一段"揉成一坨"的提示词

别急着学概念。先看看大多数人写的提示词长什么样，问题在哪。

假设你要做一个"客服回复助手"。很多人第一次会这么写：

# 一坨版（真实初学者写法）
你是一个客服，帮我回复客户的邮件。客户邮件发给你之后你就回复，
要礼貌一点，别太啰嗦，如果客户问的是退款你就告诉他7天内可以退，
如果是投诉就先道歉。回复别超过200字。用中文回复。
不要承诺你做不到的事。如果遇到你不知道的就让他联系人工客服。
回复的时候要有称呼，最后要署名"XX客服团队"。

↑ 这段提示词能用，但有三个毛病，你先自己找 30 秒。

我找完了 / 找不出来，看分析

这段提示词里，所有要求挤在一段里，没有结构。三个具体的麻烦：

① 想改一处，怕碰到别处。你想把"200字"改成"100字"，要在这一大段文字里找到那句话再改——改完你不确定会不会影响别的。

② 出问题时，不知道该改哪里。模型输出了 500 字，超了。是提示词哪句没起作用？你说不清，只能整体重写一遍碰运气。

③ 换个任务，等于重写。你现在想做一个"会议纪要整理助手"，这段提示词几乎一行都复用不了——因为角色、任务、格式、规矩全混在一起，拆不出来。

这三个麻烦分别对应分层的三个好处。下面讲五层的时候你会看到，其实就是把这段话按性质分个类，毛病就全没了。

01五层分别是什么

一句话先记住：一段完整的提示词，回答的是五个问题——你是谁 / 干什么 / 有什么规矩 / 交出什么样 / 参考什么样板。

先建立一个比喻 五层结构本质就是一份岗位说明书：给新人交代工作时，你会说「你的岗位是客服」（角色）、「这个月目标是处理退款和投诉」（任务）、「公司规定不能承诺做不到的事」（约束）、「回复要写成这个格式」（格式）、「参考这几个样板」（示例）。
你不会把这五件事搅成一段话说给新人听——为什么对 AI 就可以？
第 1 层 角色与身份层 Role

回答"你是谁"。给模型一个身份、专业背景、服务对象、说话的分寸感。

✓ 这样写有效
  • 你是 XX 公司的售后客服，负责处理退款与投诉类邮件
  • 你的专业背景是电商售后，熟悉 7 天无理由规则
  • 你的服务对象是已下单的消费者，他们大多带着情绪来
  • 语气：平静、不卑不亢，不使用感叹号
✗ 这样写基本没用
  • 你是一个世界顶级专家（虚，模型不知道该做什么）
  • 你很聪明、很厉害、经验丰富（形容词，不可执行）
  • 你是最好的客服（"最好"没有定义）
判断标准：你写的这句话，能不能翻译成"模型接下来该做什么动作"？能，就是好角色描述；不能，就是玄学。
「熟悉 7 天无理由规则」→ 能：遇到退款问题会引用这个规则。「世界顶级专家」→ 不能。
第 2 层 任务与目标层 Task

回答"你要干什么、做成什么样算好"。这是唯一必填的一层——其他四层可以省，这层不能。

✓ 这样写有效
  • 你的任务：读客户邮件 → 判断属于哪一类 → 按对应策略起草回复
  • 判断标准：客户看完后不需要再追问就能知道下一步该做什么
  • 不要做的事：不要替客户做决定，不要主动推销
✗ 这样写太虚
  • 帮我回复邮件（回复成什么样算好？没说）
  • 处理好客户问题（"处理好"没有定义）
  • 尽量让客户满意（不可衡量）
这层的核心是可验收。写完任务层，问自己一句：我拿到输出后，能不能判断它达没达标？能判断，就写对了；只能凭感觉，就还得补。
第 3 层 约束与边界层 Constraints

回答"什么不能做、遇到边界情况怎么办"。这是新手最容易漏、漏了最容易出事的一层。

✓ 这样写有效
  • 禁止：不得承诺退款到账的具体日期
  • 禁止：不得透露内部流程或其他客户信息
  • 边界：若客户询问的问题超出售后范围，回复"建议您联系人工客服"并停止
  • 边界：若邮件信息不足以判断类别，先向客户追问，不要猜
✗ 这样写等于没写
  • 不要乱说（什么是"乱说"？）
  • 注意合规（哪条合规？）
  • 不确定时谨慎处理（怎么算谨慎？）
约束层必须写"两件事"：① 明确禁止什么；② 遇到触发条件时该做什么动作。只写①不写②，模型遇到边界情况会自己瞎发挥。
第 4 层 输出格式层 Output Format

回答"交出来的东西长什么样"。结构、字段、长度、语气、顺序——凡是"能看见的形状"都归这层。

✓ 这样写有效
  • 输出三部分：称呼 / 正文 / 署名，用空行隔开
  • 正文不超过 3 句话，总字数不超过 200 字
  • 结尾固定写：「XX客服团队」
  • 只输出回复正文，不要输出你的分析过程
✗ 这样写不可验证
  • 简洁一点（多少字算简洁？）
  • 语气好一些（什么是好？）
  • 格式清晰（什么格式？）
检验方法：格式层里每一条，都应该能被一眼看出有没有违反。"不超过 200 字"能查，"简洁一点"查不了。
这也是 Day 2 要学的结构化输出的落点——格式层写死了，就能要求模型直接吐 JSON。
第 5 层 示例与上下文层 Examples & Context

回答"参考什么样板、基于什么材料"。示例给"照着做"，上下文给"依据这些"。Day 3 的 Few-shot 就落在这层。

✓ 这样写有效
  • 示例：给出 2–3 组「客户邮件 → 回复」的成对样板
  • 示例覆盖不同类型：退款 / 投诉 / 咨询各一个
  • 上下文：附上你们的退款政策原文，让模型引用真实条款
✗ 这样写会坏事
  • 三个示例都是同一种类型（模型只会处理这一种）
  • 示例的格式和第 4 层说的不一致（模型会跟着示例走，格式层白写）
  • 示例本身写错了（比没有示例更糟）
这层有一条硬规律：示例赢过描述。当第 4 层说的格式和示例里实际的格式冲突时，模型通常跟着示例走。所以示例的格式必须和你要求的格式严格一致——这是新手最常踩的坑之一。
关于顺序：五层的排列顺序不唯一，常见是「角色 → 任务 → 约束 → 格式 → 示例」。但覆盖面必须全，顺序可以调。 唯一有讲究的是：约束层别压在最末尾——长提示词里靠后的内容容易被模型"淡忘"，把"禁止做什么"放在中间或靠前更稳。

02到底为什么要分层

这是本教程的核心。三个好处，每个都配一个"看得见的差别"。

好处一：可复用 —— 换任务只改一层

把开场那段提示词分层之后，你会发现：角色、约束、格式三层其实跟"回邮件"这个具体任务无关，它们描述的是"你希望这个客服助手是个什么样的人、守什么规矩、交出什么形状"。

所以只要换掉第 2 层（任务），同一个助手立刻变成另一个工具：

# 换掉第 2 层，其他四层原样不动

【任务层 · 换成这个】
你的任务：读一段客户与客服的聊天记录 → 判断这个客户最终有没有解决问题 →
输出一段 50 字以内的内部备注，供下一任客服接手时快速了解情况。

【其他四层：一行不改】
角色层、约束层、格式层、示例层保持不变

↑ 一个「客服回复助手」，改一层就变成了「会话交接摘要助手」。如果不分层，你得从头再写一遍。

好处二：可调试 —— 出问题直接定位到层

这是分层最实用的价值。模型输出不对时，对照症状查层，而不是整体重写碰运气：

你看到的症状问题出在哪层怎么改
语气不对（太热情/太生硬）角色层补一句具体的语气要求，别写"语气好一点"
做的事不对（答非所问、漏了环节）任务层把任务拆成明确步骤，补上"做成什么样算好"
越界了（承诺了不该承诺的、瞎编信息）约束层补一条明确禁止 + 触发时该做什么动作
形状不对（太长、结构乱、夹带废话）格式层把格式写成可验证的硬指标（字数、字段、分段）
口径飘（同类问题这次这样下次那样）示例层补覆盖不同情况的示例，统一格式（Day 3 详讲）
没有分层时，这五种症状你只能整体重写；分层后，你改的是一层，其他四层不受影响。这张表建议存下来，后面四天都会用到。

好处三：可替换 —— 局部换掉不牵动全局

示例层尤其明显。你想让助手支持新业务（比如新增了"换货"类型），只需在示例层加一组示例：

【示例层 · 新增一组】
例 3（换货）
客户邮件：收到的鞋子尺码不合适，能换大一码吗？
回复：您好，支持 7 天内无理由换货……

【其他四层：不动】

↑ 角色、任务、约束、格式完全不动，助手就学会了新业务。这是"示例层可替换"带来的直接好处。

一个额外好处 可分工。团队里做提示词时，业务同事负责任务层和示例层（他最懂业务），你负责约束层和格式层（你最懂模型）。分层之后各改各的，不会互相覆盖。这是专业团队都在用这套结构的原因。

03实操：把一坨拆成五层

把开场那段坏提示词，逐句归类，然后重写。

第一步：逐句标注属于哪一层

你是一个客服，帮我回复客户的邮件。          ← 角色层 + 任务层（混在一起了）
客户邮件发给你之后你就回复，                ← 任务层
要礼貌一点，别太啰嗦，                      ← 角色层（语气）+ 格式层（长度）混写
如果客户问的是退款你就告诉他7天内可以退，    ← 任务层（策略）
如果是投诉就先道歉。                        ← 任务层（策略）
回复别超过200字。                            ← 格式层
用中文回复。                                  ← 格式层
不要承诺你做不到的事。                        ← 约束层
如果遇到你不知道的就让他联系人工客服。        ← 约束层
回复的时候要有称呼，                          ← 格式层
最后要署名"XX客服团队"。                      ← 格式层

↑ 看出来了吗：格式层的要求散落在 5 个不同位置，约束层的两句话被夹在中间。这就是"不分层"的真实代价。

第二步：归拢重写

# 角色层
你是 XX 公司的售后客服，负责处理退款、换货与投诉类邮件。
你的服务对象是已下单消费者，他们大多带着情绪。语气平静、不卑不亢，不使用感叹号。

# 任务层
你的任务：读客户邮件 → 判断属于「退款 / 换货 / 投诉 / 咨询」哪一类 → 按对应策略起草回复。
判断标准：客户读完不需要再追问，就知道下一步该做什么。

# 约束层
禁止：不得承诺退款到账的具体日期，不得透露内部流程或其他客户信息。
边界：若邮件信息不足以判断类别，先向客户追问，不要猜。
边界：若问题超出售后范围，回复「建议您联系人工客服」并停止。

# 格式层
输出三部分：称呼 / 正文 / 署名，中间用空行隔开。
正文不超过 3 句话，总字数不超过 200 字。
结尾固定写：「XX客服团队」。
只输出回复正文，不要输出你的分析过程。

# 示例层
例 1（退款）
客户邮件：我上周买的耳机不想要了，能退吗？
回复：您好，订单支持 7 天内无理由退货……
（另附：退款 / 投诉 / 咨询 各一组示例，格式与上面严格一致）

↑ 同样的内容，分层之后：能改、能定位、能复用。字数差不多，效果天差地别。

✋ 停下来，自己做一遍（3 分钟）

别往下读。翻出你上周吴恩达课程里写过的一个提示词，用五种颜色（或①—⑤标记）把每一句标进五层。

做完再看下一步。你大概率会发现：任务层写得很详细，但约束层和格式层基本是空的——几乎所有初学者都这样。

04五个练习（从易到难）

练习是这 45 分钟里最值钱的部分。建议全部做完，至少做完 1、2、5。

练习 1 · 找缺失的层（5 分钟）

下面这段提示词，哪几层完全没写？缺了会导致什么后果？

你是一位资深数据分析师。
帮我分析这份销售数据，找出问题并给出建议。
要专业一点。
参考答案

写了的：角色层（资深数据分析师）、任务层（分析数据、找问题、给建议）——但任务层很虚。

完全没写的：约束层、格式层、示例层，三层全空。

后果：

① 没格式层 → 模型可能输出一大段自说自话的分析，你要的内容埋在第 8 段；

② 没约束层 → 数据里没有的信息它也会编（比如"建议开拓华东市场"，但数据里根本没有华东数据）；

③ 没示例层 → 每次输出的粒度、口径都不一样，没法对比。

最该补的一条：格式层。加一句"输出三部分：发现的问题（不超过3条）/ 每条对应的证据（引用数据中的具体数字）/ 建议动作（不超过3条）"，效果立刻不一样。

练习 2 · 判断一句话属于哪层（5 分钟）

下面 6 句话，分别属于哪一层？

A. 若用户提供的信息不足以判断，先追问，不要自行假设
看答案

约束层。典型的"边界 + 触发动作"写法。

B. 输出用 JSON，字段为 category、confidence、reason
看答案

格式层。而且这条是 Day 2 结构化输出的落点。

C. 你的服务对象是刚入职的新人，他们看不懂专业术语
看答案

角色层。限定服务对象和表达分寸。

D. 每条建议后面必须附上数据中的具体数字作为依据
看答案

格式层 + 约束层的交叉。它规定了输出形状（格式），也禁止了无依据输出（约束）。一句话跨两层是正常的，不用强行拆开。

E. 例：输入"这个东西不好用" → 输出 负面
看答案

示例层。Day 3 的 Few-shot 就在这里。

F. 你的任务是判断这段评论的情感倾向，准确度要达到九成以上
看答案

任务层。而且它给出了可验收标准（九成以上），是好写法。

练习 3 · 拆一段真实的系统提示词（20 分钟，本日重点）

找一段真实存在的 system prompt 来拆。素材从这几处拿，任选：

  • GitHub 上搜 system prompt、awesome prompts，找开源项目的提示词文件
  • 你常用的 AI 产品 / 智能体的指令全文（有些会公开）
  • 别人分享的提示词合集（中英文各找一段，中文的更贴近你的真实使用场景）

拆解要求：

  1. 逐句标进五层，用不同颜色或 ①—⑤ 标记
  2. 标完之后回答两个问题：哪一层写得最厚？哪一层是空的？
  3. 找出至少一处跨层混写的句子（比如角色和格式写在一句里）
  4. 限时 15 分钟一段，别抠细节——你要练的是直觉，不是做标注作业
做这个练习时留意一个现象：你会发现写得好的提示词，五层的厚度是不均匀的——通常任务层和格式层最厚，角色层只有一两句话。这很正常。分层不等于平均分配字数，该厚的厚、该薄的薄。

练习 4 · 改一段有病的提示词（10 分钟）

下面这段提示词分层了，但每层都有毛病。找出至少 3 处并改写。

# 角色
你是世界上最顶尖的翻译专家，精通所有语言。

# 任务
帮我把用户给的文本翻译好。

# 约束
不要出错，要准确。

# 格式
输出要清晰美观。

# 示例
例1：Hello → 你好
例2：Hi → 你好
例3：Hey → 你好
参考答案（至少能找出 5 处）

① 角色层玄学。「世界顶尖、精通所有语言」不可执行。改成「你是中英技术文档译者，术语优先采用 XX 行业标准译法」。

② 任务层没有验收标准。「翻译好」没定义。补上「目标读者是中文开发者，要求术语统一、句式符合中文技术文档习惯」。

③ 约束层空话。「不要出错，要准确」等于没说。改成「不得增删原文信息；遇到无法确定译法的专有名词，保留英文原词并在括号中标注」。

④ 格式层不可验证。「清晰美观」查不了。改成「只输出译文，不加任何说明；保留原文的段落与列表层级」。

⑤ 示例层三个例子一模一样。全是打招呼 → 你好，模型只学会了这一个模式。换成覆盖不同情况：一句陈述句、一句带术语的句子、一句长句。

⑥ 示例层缺失最重要的一类。没有示例告诉模型「遇到专有名词怎么办」——而这恰恰是最容易出错的地方。

练习 5 · 搭你自己的五层模板（15 分钟，今天的产出物）

写一个通用模板，以后写任何提示词都从它出发。要求：五层各写一句占位句 + 每层 3 条"可填内容"提示。下面是可以抄的骨架，你要做的是按你的实际场景把它填实。

# 角色层
你是【身份】，服务于【对象】。
你的专业背景是【领域】，熟悉【具体规则/标准】。
语气：【分寸描述，要能翻译成具体动作】。

# 任务层
你的任务：【步骤1】→【步骤2】→【步骤3】。
判断标准：【做到什么算达标，必须可观察】。
不做的事：【明确排除】。

# 约束层
禁止：【具体禁止项，2-3条】。
边界：若【触发条件】，则【具体动作】。
边界：若信息不足，【追问 / 停止 / 采用默认值】。

# 格式层
输出结构：【几部分、各部分是什么】。
长度限制：【字数 / 条数】。
固定元素：【署名、标题、分隔符等】。
只输出【什么】，不要输出【什么】。

# 示例层
例1（常见情况）：输入… → 输出…
例2（边界情况）：输入… → 输出…
例3（棘手情况）：输入… → 输出…
（所有示例格式必须与格式层严格一致）
把这份模板存到你能随时找到的地方。本周后面四天都会用到它——Day 2 的结构化输出写在格式层，Day 3 的 Few-shot 写在示例层，Day 4 的 CoT 写在任务层。它就是你这一周的地基。

05三个必须记住的坑

1

约束层压在最末尾

很多人把"不要做什么"写在提示词最后一句。长提示词里靠后的内容容易被淡化。把约束层放在中间或靠前，格式层放后面——因为格式紧贴着输出，反而不容易丢。

2

示例和格式层打架

格式层说"输出 JSON"，示例里给的是一段自然语言。模型会跟着示例走，格式层白写。写完示例，回头核一遍：示例的实际格式，和格式层描述的一致吗？

3

以为分层就是"分五个标题"

加了 # 角色 # 任务 五个标题，但每个标题下面塞的还是一大段混写内容——这不算分层。判断标准不是有没有标题，是改一层时会不会碰到另一层。

06怎么算学懂了

对应 Day 1 的通过标准。三条都要过，建议闭卷自测。

今日达标清单

  • 能不看资料说出五层：名称 + 每层回答什么问题 + 每层一个典型写法。五层全对才过，卡住一层就回去看第 01 节。
  • 拿到陌生提示词能标层：10 分钟内完成逐句标注，准确率 ≥ 80%。拿练习 3 那段自测，或者再找一段新的。
  • 手上有一份自己的五层模板：不是抄我给你的骨架，是按你的实际场景填过内容的版本。
  • 能说出分层的三个好处，并且每个能举出一个具体场景（不用背定义，说出"什么时候能感受到它有用"就行）。

最后一道检验题：不看教程，解释一句话——为什么"分层之后，改一处不会碰坏别处"？
答得上来，今天这 45 分钟就没白花。答不上来，回到第 02 节把三个好处各看一遍。

今天剩下的时间怎么安排 学完这 45 分钟后：练习 3（拆真实提示词，20 分钟）+ 练习 5（搭模板，15 分钟）+ 练习 1 和 2（10 分钟）是必做的主线，约 45 分钟。
练习 4 和"回头改自己上周的旧提示词"是加分项，时间够就做。做不完不要拖到明天——明天的结构化输出要建立在今天的模板上。
