W3 任务五 · 上下文窗口的实际限制教程

目标：理解"长文档怎么塞、超了怎么办"　·　记录日期：2026-10-25　·　数字以各模型官网为准（❓ 见文末）

一、先搞懂：上下文窗口是什么

模型每次回答时，面前摊着一份有大小限制的完整档案。这份档案里装着：系统规则（你的人设/prompt）+ 你们之前所有的对话 + 它之前调用工具读到的内容 + 本次你新发的输入 + 它正在"思考"的过程。

这份档案的容量上限，就是上下文窗口（context window），用 token 计量。

硬件比喻（三个任选）：
  • 一块 RAM / FIFO 缓冲区的深度——深度定了，超过就装不下
  • 示波器的屏幕——一屏只能显示那么多采样点，超出的历史直接滚出视野
  • 一张有字数限制的草稿纸——写满了，后面的内容要么挤掉前面的，要么写不进去

还有一个反直觉但极重要的点：每问一轮，它都要把这份档案从头到尾重读一遍再回答。所以聊得越长 → 每轮要重发的档案越大 → 越慢、越贵、越容易在长尾处"变笨"。这正好接上你任务三算的成本：窗口越大、历史越长，token 越费钱。

关键提醒：中文约 1 token ≈ 1~2 字。一篇几千字的技术文档，在任何一路模型里都"只占一格"，普通长文根本碰不到上限。
真正让长文"白写"的，通常不是字数超限，而是下面第三节讲的三件事。数字会变、且按长度/档位分档，以你跑任务当天官网为准 ❓。

三、长文档"塞不进/塞进也白搭"的三个真相

  • ① 抓取侧单页截断：很多系统把网页/文档搬进来时，对单页长度有实际上限，超出的部分这轮根本没进档案，不是"以后爬"，是"没写进去"。
  • ② 切块后只取靠前候选：进来的长文会被切成块，问答时按相关度取 Top-K（常见 5~20 块）。关键句若落在后排块、相关度又不突出，照样进不了答案。
  • ③ 中段衰减（lost in the middle）：即使窗口够大，模型对长文本中间部分的有效注意力也会下降——两头强、中段弱。中间那些"承上启下"的过渡段，模型眼里信息密度接近零。
可操作结论：单篇正文压到 约 3000 中文字（6000~8000 token），把结论和前三句放在前 800 字内，比单纯纠结总字数有用得多。这也是为什么要把长文拆成多篇——不是为了缩短，是为了让每篇都能被完整吃进检索。

四、长文档怎么塞（四种办法，按需选）

办法怎么做适用场景
① 直接塞全文直接进上下文（文档 < 窗口的 60%）短文档、单次问答，最省事
② 切块 (chunking)切成不超过窗口的块，逐块处理再汇总中等长文，本地脚本就能做
③ 检索增强 (RAG)先建索引/向量库，用时只取相关片段进窗口知识库、文档海量、要长期复用
④ 摘要前置 + 长窗口先压成摘要再进窗口；或换 1M 窗口模型要保全局观、且预算够
和你最相关的一条：你规划里的 EMC 案例库，本质就是方法 ③ RAG 的最佳实践——22 条 EMC 案例先建向量库，问答时只把"最相关那几条"喂进窗口，既不超窗口，又避开中段衰减。方法 ③ 比硬塞全文，对你这个场景是降维打击。

五、超了怎么办（超限的处理 + 自己怎么防）

平台怎么处理超限

  • 截断：不同平台丢的位置不同——有的丢最早的历史（保留最新），有的丢中间，有的只保留首尾。这会让"中段衰减"雪上加霜。
  • 直接报错：不少 API 超出上限直接返回 400，调用失败。
  • 自动压缩：少数平台把超长历史自动摘要压缩，但压缩会丢细节。

你自己必须做的四件事

  • 估算 token：用任务三的方法（中文 ×1.5 粗估，或看 API 返回的 usage）先算，别凭感觉。
  • 留余量：窗口只用到 60~70%，别顶满——还要给输出留位置（看第一节那张图）。
  • 关键信息放头尾：结论、约束、最关键的指令写在前 800 字和结尾，避开中间遗忘区。
  • 监控 usage：调用后看 prompt_tokens / completion_tokens / total_tokens，超阈值就切 RAG 或切块。

六、和前几篇串起来

  • 任务一（API 主线）：上下文窗口限制直接卡在"发请求"那一步——请求体（输入）大小受窗口约束。
  • 任务三（token 成本）：长文档 = 输入 token 暴涨（还可能触发分档更贵），窗口越大越贵。算月成本时别漏了历史对话的累积。
  • 任务四③（文档批量转换）：批量处理长文档的工程化，正是"切块 / RAG"的前置步骤。
  • 你的 EMC 案例库目标：= 方法③ RAG 的落地，完美避开本篇所有坑。

七、自查三问（能答出即过关）

  • 为什么说"普通长文碰不到窗口上限，却还是白写"？
    答：因为瓶颈常是抓取截断、切块只取 Top-K、中段衰减，不是字数超限。
  • 窗口 25 万 token，为什么不能把 25 万全用来放输入？
    答：窗口 = 系统+历史+输入+思考+输出 的总和；输入塞满就没地方放输出，且历史越长越贵越慢。
  • EMC 案例库为什么该用 RAG 而不是全文硬塞？
    答：只取最相关片段进窗口，既不超窗口，又避开中段衰减，还能长期复用、成本可控。
