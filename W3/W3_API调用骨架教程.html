W3 任务六 · 看懂 API 调用骨架教程

目标：发请求 → 拿 JSON → 取字段 → 写文件；能自己改 API key 和参数跑通　·　记录日期：2026-10-25
任务六和任务一是什么关系？ 同一根主线，但这次要求变了：不是"看懂"，是"能改 key、改参数、真跑通"。 因为这条四步骨架 = 你以后读任何 AI 脚本的通用模板——无论它调的是 DeepSeek、OpenAI、还是你自家服务，骨架都一样，变的只是 URL、key 和参数。

一、四步骨架（硬件比喻，和任务一一致）

二、先看"免 key 版"：没账号也能跑通骨架

先用一个不用申请 key 的公开接口，让你看到四步完整跑通（拿北京实时气温）：

import requests

url = "https://api.open-meteo.com/v1/forecast"
params = {"latitude": 39.90, "longitude": 116.40, "current": "temperature_2m"}  # ← 改这里换地点

r = requests.get(url, params=params)        # ① 发请求
data = r.json()                            # ② 拿 JSON
temp = data["current"]["temperature_2m"]    # ③ 取字段

with open("weather.txt", "w", encoding="utf-8") as f:  # ④ 写文件
    f.write(f"北京当前气温 {temp} ℃")
print("已写入 weather.txt，气温 =", temp)

跑法：装一次 requests（pip install requests），存成 demo.py，python demo.py。能看到生成 weather.txt 就算骨架跑通。

三、再看"真 LLM 版"：这就是你要改 key/参数的那个

下面是调 DeepSeek 的最小骨架（用最朴素的 requests，不依赖 SDK，骨架看得最清楚）：

import requests, os

API_KEY = os.environ.get("DEEPSEEK_API_KEY")   # ← 改这里：从环境变量读 key（别写死明文）
url = "https://api.deepseek.com/chat/completions"

payload = {
    "model": "deepseek-v4-flash",              # ← 改这里换模型
    "messages": [{"role": "user", "content": "用一句话解释什么是 EMC"}],  # ← 改这里换问题
    "temperature": 0.3,                        # ← 改这里调风格（低=稳，高=发散）
    "max_tokens": 200                          # ← 改这里限长度
}
headers = {"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"}

r = requests.post(url, json=payload, headers=headers)  # ① 发请求
data = r.json()                                    # ② 拿 JSON
text = data["choices"][0]["message"]["content"]     # ③ 取字段

with open("emc.txt", "w", encoding="utf-8") as f:   # ④ 写文件
    f.write(text)
print("已写入 emc.txt：", text)

这两样，就是任务六要你"能自己改"的

  • 改 keyAPI_KEY：去 DeepSeek 平台复制你的 key，不要写死在脚本里。用环境变量传： 
    # Windows PowerShell 里先设（关掉窗口就失效，安全）
$env:DEEPSEEK_API_KEY = "sk-你的key"
python demo_llm.py

# 或 Linux / Git Bash
export DEEPSEEK_API_KEY=sk-你的key
python demo_llm.py
  • 改参数payload 里那四个： model（换模型）、messages[0].content（换问题）、temperature（0~1，低稳高活）、max_tokens（输出上限）。改完直接重跑即可。
端点与模型（以官网为准 ❓）：DeepSeek 官方 OpenAI 兼容端点 https://api.deepseek.com/chat/completions。 注意 deepseek-chat / deepseek-reasoner 已于 2026-07-24 弃用，现用 deepseek-v4-flash（便宜）/ deepseek-v4-pro（强）。 换成 OpenAI 只需改 url + model + key，骨架完全不变——这就是"通用骨架"的意义。

四、两个真实坑（跑不通多半是它俩）

现象最可能原因怎么改
401 报错key 错 / 没设环境变量 / Bearer 拼错核对 DEEPSEEK_API_KEY 是否已 export，headers 里写了 Bearer
取字段报 KeyError返回的不是你想的结构（常因出错时返回 {"error":...}）先 print(data) 看真实结构，再决定取哪个键；出错时别直接取 choices
卡住/超时网络不通 / 端点错 / 公司代理拦截呼应任务一：任何请求都要设超时，如 requests.post(..., timeout=30)
安全 + 数据红线（两件事）
① key 别泄露：永远别把 sk-... 明文写进脚本再提交到 git / 发群里。环境变量或密钥管理才是正道。
② EMC/公司专有数据别喂进云端 API：这个 LLM 版示例是"公开问题（什么是 EMC）"，练手 OK；真要处理你的案例库，走本地部署或合规通道。

五、和前几篇串起来

  • 任务一：这条主线就是任务一那套的"代码兑现版"——当时讲概念，现在给你能跑的骨架。
  • 任务三（token 成本）：max_tokens 就是任务三算月成本时的"输出上限"；每次调用的 usage 字段能直接读出真实 token 数。
  • 任务四（自动化）：自动化里每个"调用大模型"的节点，底层就是这四步；读懂骨架，你才看得懂那些节点在做什么。
  • 任务五（上下文窗口）：messages 里累积的历史越长，越逼近窗口上限——和任务五的"档案"比喻是一回事。

六、自查三问（能答出即过关）

  • 四步骨架是哪四步？
    答：发请求 → 拿 JSON → 取字段 → 写文件。
  • 想换一个问题/换一个模型，动脚本哪几行？
    答：payload 里的 model 和 messages[0].content；不用动骨架其它部分。
  • 为什么 key 要用环境变量而不是写死在代码里？
    答：防止泄露——明文 key 一旦进 git / 聊天记录就曝光了，环境变量或密钥管理才安全。
端点/模型取自 DeepSeek 官方 API 文档（2026-10-25 核验）：base_url https://api.deepseek.com，模型 deepseek-v4-flash/v4-pro；deepseek-chat 已于 2026-07-24 弃用。厂商可能调整，以你跑任务当天官网为准 ❓。
