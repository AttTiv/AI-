使用说明：「必填态」四档——必填 一线必须填；条件必填 满足触发条件才必填（触发条件写在备注列）；非必填 可选；系统自动 由系统生成不手工填。 「显示」勾选决定该字段是否出现在表单上。配置好后务必点「导出 JSON」留存——本地保存只是缓存，VDI 环境可能被清除，JSON 文件才是可靠备份，也是给 IT / 建表同事的交付依据。
认证合规：判定分四档，不要一刀切
关键区别——「改了没有」和「要不要报备 / 要不要送检」是两件事。DEF-031 只回答第一件；第二件由 DEF-034 判定。 改了不等于要送检，而要送检也不等于必须先送检才能改 —— 缺陷可以先整改，整改完再送检，但送检样机必须提前备。
DEF-034 判定结果要不要报备要不要送检流程（关键节点顺序）
① 无需报备不报备不送检整改 → 内部验证 → 关闭。最快路径
② 仅需报备需报备不送检备案 → 拿到回执 → 整改 → 内部验证 → 关闭
③ 报备且需送检需报备需送检备案 → 整改与样机准备并行 → 内部验证 → 寄样送检（全项约 3 个月）→ 送检通过 → 关闭
④ 待认证机构确认待定待定只允许先做围堵 / 临时对策；永久变更暂缓，等确认后再落②或③
为什么③必须「整改与样机准备并行」：送检样机不是整改完才想起来做的。等整改完再备样机，等于在 3 个月送检周期前面再排一段备料期，缺陷闭环时间被无谓拉长。 判定为③的当天，DEF-038 就该从「未启动」开始动。
为什么③的内部验证通过不能直接关：内部验证只证明「缺陷修好了」，不证明「认证仍然有效」。DEF-043 验证结论后面还压着一道 DEF-040 送检结论。
