W3 任务二 · 装 Dify / n8n，跑通第一个工作流

主线：选一个工具 → 装好（本地 Docker 或云端）→ 拖出第一个工作流 → 点一下能跑出结果。目标：一次看懂"工作流"是什么、怎么落地。

💡 一句话先入脑：工作流（Workflow）就是你画的一条"自动化产线"——把一个个"工位"（节点）用"传送带"（连线）串起来：上一个工位的产出，自动喂给下一个工位。Dify / n8n / 扣子，就是三种不同档次的"产线控制台"。你这周的任务，就是任选一个，把产线搭起来、让第一个产品（数据）走通。

零、先回答你的问题：扣子能不能用？

能用，而且是你"最快跑通"的一条路。 扣子（字节跳动的 Coze）本质就是一个云端、零安装、中文界面的可视化工作流 + AI 智能体平台，拖节点连线的玩法和 Dify/n8n 一模一样。

但三家定位不同，给你一张"选谁"速查表：

维度Dify（开源）n8n（开源）扣子（字节 SaaS）
装不装本地 Docker 或 云端版本地 Docker 或 云端版不用装，开网页就用
擅长造 AI 应用（自带知识库 RAG、模型管理）通用自动化（连 API/数据库/定时，AI 只是其中一类节点）造 AI 对话机器人 / 智能体
数据在哪本地/你自己的服务器本地/你自己的服务器在字节云端
要 API Key 吗AI 步骤要（如 DeepSeek）看接什么，AI 步骤要基础不用（内置豆包模型）
上手难度中（要会 Docker）中（要会 Docker）最低

巴蒂的推荐（结论先行）：

  • 只想最快建立"工作流"直觉、零门槛 → 先用扣子跑通第一个，10 分钟见效。
  • 想练"自己拥有、数据不出厂"的真部署能力（这更贴合你"硬件/制造+AI"、以后要把 EMC 案例库本地化的目标）→ 用 Dify 本地 Docker。
  • 想做的是"连数据库、定时抓数、调各种 API"这种通用自动化（不止 AI）→ 用 n8n。

⚠️ 一条硬规矩（给你记死）：你的 EMC 专有案例数据属于公司资产，别往扣子或任何纯云端免费版里喂。那等于把涉密数据传出境。先用扣子练手感、用假数据；真要接 EMC 数据，等本地 Dify 搭好、数据留在你自己机器上再说。

一、三个比喻，先建立画面

  • 工作流 = 一条产线：开始 → 工序1 → 工序2 → … → 结束，产品（数据）从头走到尾。
  • 节点（Node）= 一个工位 / 一道工序：比如"调用大模型""发 HTTP 请求""写数据库""发企业微信"，每个节点干一件具体活。
  • 连线 = 传送带：上一个节点的输出，自动成为下一个节点的输入。
  • Docker = 把整套车间连同地基一起打包：你不用逐个装依赖，拉来一个"集装箱"里面啥都齐了，开机即用。这就是为什么本地装推荐 Docker——省掉一堆环境坑。

二、路线 A：Dify（本地 Docker，最贴合你目标）

前提：装好 Docker Desktop（Windows 用 WSL2 后端）。先跑 docker compose version 确认 ≥ 2.24.0；机器至少 2 核 / 4GB 内存（你的 VDI 若带不动，就改用下面的"云端版"，任务说"本地或云端都行"）。

安装步骤

# 1) 拉代码
git clone https://github.com/langgenius/dify.git
cd dify/docker

# 2) 生成配置
cp .env.example .env

# 3) 一键启动（会拉起 7 个核心服务 + 8 个依赖组件，首次较慢）
docker compose up -d

# 4) 看是否都起来了（状态应为 Up / healthy，init_permissions 显示 Exited 是正常的）
docker compose ps

启动后浏览器开 http://localhost/install 设管理员账号 → 登录 http://localhost。

跑通第一个工作流

  • 左侧"工作室"→ 创建应用 → 选 工作流（Workflow） 或 聊天流（Chatflow）。
  • 画一条最简链：开始 → LLM（大模型） → 结束。
  • 先去"设置 → 模型供应商"配一个模型（填 DeepSeek 或 OpenAI 兼容的 API Key）。
  • 点右上角运行 / 预览，输入一句话（如"用一句话解释 EMC"），看到 AI 回复 = 跑通 ✅。

想接你的 EMC 知识？ Dify 自带"知识库（RAG）"：把文档传上去，工作流里加一个"知识检索"节点，AI 就能基于你的资料回答。这正是你转型目标的第一步——但先在本地跑、别用云端。

三、路线 B：n8n（本地 Docker，通用自动化首选）

⚠️ 重要变化（2026-10 起）：n8n 从 v3 开始弃用 npm 安装，新装一律走 Docker。所以别再用 npx n8n 了，下面是正确的 Docker 姿势。

# 1) 建一个持久化数据卷（你的工作流存这里，容器重启也不丢）
docker volume create n8n_data

# 2) 启动（后台 -d，映射到 5678 端口）
docker run -d --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n

浏览器开 http://localhost:5678 设 owner 账号。

跑通第一个工作流

  • 新建 Workflow → 拖一个 Manual Trigger（手动触发，方便调试）。
  • 再拖一个 HTTP Request 节点：方法 GET，URL 填一个公开接口（如 https://api.chucknorris.io/jokes/random 这种免 key 的测试接口）。
  • 连起来，点Execute Workflow（执行），下方能看到 HTTP 返回的 JSON = 跑通 ✅。
  • 想加 AI：再拖 OpenAI / DeepSeek 节点，配 Key 即可。

硬件比喻：n8n 就像一台"万能接线排"——不光能接 AI，还能接数据库、Excel、定时器、企业微信。你以后要做"BOM 审核自动跑、结果发群里"这种杂活，n8n 最顺手。

四、路线 C：扣子（云端零安装，最快见效）

适合：只想立刻看到"工作流长啥样"，不想碰 Docker/命令行。打开网页就能干。

  • 打开 coze.cn 注册登录（国内版；海外是 coze.com）。
  • "创建 Bot" → 进入编排页，点"工作流"添加一条。
  • 拖节点：开始 → 大模型 → 结束。
  • 大模型节点默认用内置豆包模型，不用填 Key。
  • 点"试运行"，输入测试内容，看到输出 = 跑通 ✅。

提醒回扣前面：扣子练手用假数据；真接 EMC 专有数据前，请回到路线 A 的本地 Dify。

五、"跑通"的通用验收标准

  • 1 能跑：点执行不报错，节点变绿/显示成功。
  • 2 能看到结果：输出的内容是你预期的（AI 回了话 / API 回了数据）。
  • 3 能改：你调一下节点参数（换个提问、换个接口），再跑一次结果跟着变——说明你真懂了这条链，不是瞎蒙。

六、新手最常踩的坑

  • 坑1 Docker 没装 / 版本太低：Dify 要 Compose ≥ 2.24.0。先 docker compose version 自查。
  • 坑2 机器带不动：Dify 吃 4GB+ 内存，VDI 资源紧就改用云端版（Dify Cloud / n8n Cloud / 扣子）。
  • 坑3 端口被占：5678 / 80 被别的程序占了，启动报错。换端口或关掉占用的程序。
  • 坑4 AI 节点没配 Key：Dify/n8n 的模型节点空白报错，先去填 DeepSeek/OpenAI Key；扣子用内置模型可跳过。
  • 坑5 把涉密数据喂云端：再强调一次，EMC 专有案例别进扣子/免费云端。

七、验收自测（能答出＝这任务过关）

第 1 题：工作流里的"节点"和"连线"分别比喻成车间里的什么？

答：节点 = 一个工位 / 一道工序（干一件具体活）；连线 = 传送带（上一工位的产出自动喂给下一工位）。

第 2 题：Dify 和 n8n 各最擅长什么？用 Docker 装 n8n 为什么别用 npx n8n 了？

答：Dify 擅长造 AI 应用（自带知识库/模型管理）；n8n 擅长通用自动化（连 API/数据库/定时）。n8n 从 v3（2026-10）起弃用 npm，新装只走 Docker。

第 3 题：扣子能不能替代它们？你打算怎么选？

答：能，用于"最快跑通/零门槛"；但数据在字节云端。我的建议：练手用扣子（假数据），真做 EMC 本地化用 Dify 本地 Docker，通用自动化用 n8n。
